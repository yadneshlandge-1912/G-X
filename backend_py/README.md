# CoalMine LoRa+AI — Python Backend

FastAPI + asyncio backend for the underground coal mine monitoring platform.  
Runs entirely offline — no cloud, no internet, no SIM card required.

---

## Stack

| Layer | Technology |
|-------|-----------|
| Web framework | FastAPI 0.111 |
| Async runtime | asyncio (built-in) |
| WebSocket | `fastapi.WebSocket` + `websockets` |
| Database | SQLite 3 (built-in `sqlite3`) — WAL mode |
| Serial I/O | pyserial 3.5 |
| Config | python-dotenv |
| Tests | pytest + pytest-asyncio |
| Python version | ≥ 3.11 |

## Quick Start

### 1. Install dependencies

```powershell
cd G-X\backend_py
pip install -r requirements.txt
```

### 2. (Optional) Configure serial port

Create a `.env` file:
```
SERIAL_PORT=COM3        # Windows — or /dev/ttyUSB0 on Linux/Pi
PORT=3001
```

If `SERIAL_PORT` is omitted, the backend auto-starts in **simulation mode** —  
all 5 nodes generate realistic live data with no hardware needed.

### 3. (Optional) Seed demo data

```powershell
python seed.py
# Inserts 1 hour of readings: gas spike on Node 4, SOS on Node 3
```

### 4. Start the server

```powershell
python server.py
```

Output:
```
═══════════════════════════════════════════════════════

  API  : http://0.0.0.0:3001/api
  WS   : ws://0.0.0.0:3001/ws
  Docs : http://0.0.0.0:3001/docs   ← Swagger UI (free!)
  DB   : data/coalmine.db
═══════════════════════════════════════════════════════
[Agent1] Signal Receiver Agent started
[Agent2] Location Agent started
[SerialBridge] 🔵 SIMULATION MODE — 5 nodes, 2s interval
```

### 5. Run tests

```powershell
python -m pytest tests/ -v
```

Expected output (all green):
```

tests/test_signal_agent.py::TestKalmanFilter::test_smooths_noisy_signal PASSED

```

### 6. Start the React dashboard (separate terminal)

```powershell
cd ..\dashboard
npm install
npm run dev
# Open http://localhost:5173
```

## REST API

Interactive docs at **http://localhost:3001/docs** (Swagger UI auto-generated by FastAPI).

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/status` | Server + agent health |
| GET | `/api/nodes` | Latest reading per node (1–5) |
| GET | `/api/nodes/{id}/history?limit=100` | Node history |
| GET | `/api/alerts` | Unacknowledged alerts |
| POST | `/api/alerts/{id}/ack` | Acknowledge alert |
| GET | `/api/stats` | 1-hour aggregated stats |
| GET | `/api/map` | Anchor positions + latest locations |
| POST | `/api/inject` | Inject test packet (no hardware) |
| GET | `/api/sync/pending` | Offline sync queue status |
| GET | `/api/thresholds` | DGMS alert thresholds |

### Example: inject a test packet

```bash
curl -X POST http://localhost:3001/api/inject \
  -H "Content-Type: application/json" \
  -d '{"nid":1,"t":28.5,"h":72.0,"gas":350,"rssi":-85,"sos":0}'
```

### Example: simulate SOS

```bash
curl -X POST http://localhost:3001/api/inject \
  -H "Content-Type: application/json" \
  -d '{"nid":3,"t":30.0,"h":75.0,"gas":100,"rssi":-90,"sos":1}'
```

## WebSocket Events (ws://localhost:3001/ws)

| Event | Direction | Payload |
|-------|-----------|---------|
| `snapshot` | Server → Client | Full current state of all 5 nodes (on connect) |
| `reading` | Server → Client | Live enriched reading per node |
| `alert` | Server → Client | New alert (SOS, gas, temp, node lost) |
| `sos` | Server → Client | SOS activated on a node |
| `node_lost` | Server → Client | Node heartbeat lost |
| `node_discovered` | Server → Client | New node seen for first time |
| `gateway_connected` | Server → Client | Gateway serial port connected |

## Alert Thresholds (DGMS — Coal Mines Regulations 2017)

| Parameter | Caution | Warning | Danger/Critical |
|-----------|---------|---------|-----------------|
| Gas PPM (CH4/CO) | 300 | 600 | 1,000 |
| Temperature | 33 °C | 37 °C | 40 °C |
| Humidity | — | 90% | — |
| Node silence | — | 30 s | 120 s |

All values configurable in `config.py`.

## Calibration (On-site)

After deploying hardware, update two values in `config.py`:

```python
# Measure RSSI with a node at exactly 1 metre from gateway
RSSI_AT_1M_DBM = -40    # your measured value

# Fit to RSSI readings at 10m, 50m, 100m underground
PATH_LOSS_EXP  = 2.5    # 2.0–3.5 typical for mine tunnels
```

Then update `ANCHOR_MAP` with your actual surveyed positions in metres.

## Offline-First Design

```
Gateway ESP32 ──USB──► serial_bridge.py
                              │
                              ▼
                       signal_agent.py   (Agent 1)
                              │
                    ┌─────────┴──────────┐
                    ▼                    ▼
           location_agent.py      alert_engine.py
           (Agent 2)
                    │
                    ▼
                  db.py  ──► coalmine.db  (SQLite WAL)
                    │
                    ▼
              sync_queue table  ──► future cloud upload
```

- **Zero internet required** — entire stack runs on a Raspberry Pi at the pit head
- SQLite WAL mode handles concurrent reads from dashboard + writes from agents
- `sync_queue` table stores every record for future BSNL/cloud upload when connectivity is available
- Serial bridge buffers and retries if the serial port drops
